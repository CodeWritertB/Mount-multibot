# Техническое задание и архитектура бота заведения «Маунт»

Данный документ описывает структуру, функционал и логику работы многоплатформенного бота (Telegram + VK + Max) для автоматизации бронирования, оплаты и маркетинга.

---

## 1. Общая архитектура системы

### 1.1. Технологический стек
- **Backend:** Python 3.11+
- **Telegram:** aiogram 3.x
- **VK:** vkbottle или simple-vkapi
- **Max:** max-api (или max-botsdk)
- **Database:** PostgreSQL 15+
- **ORM:** SQLAlchemy 2.0
- **Cache & FSM:** Redis 7+
- **Payment:** ЮKassa API
- **Deployment:** Docker + Docker Compose

### 1.2. Архитектурные принципы
- **Единое ядро:** Общая логика бронирования, независимая от платформы
- **Единая БД:** Все платформы (Telegram, VK, Max) используют одну PostgreSQL
- **Единый Redis:** Общий кэш и FSM для всех платформ
- **Адаптеры:** Отдельные слои для Telegram, VK и Max
- **Event-driven:** Webhook-обратные вызовы от ЮKassa
- **FSM:** Машину состояний для многошаговых процессов

### 1.3. Схема взаимодействия

```python
# Псевдокод
async def handle_auth(user_id, full_name, phone, platform):
    # Поиск пользователя по ID платформы
    user = await db.get_user_by_platform(platform, user_id)
```

### 3.2. Бронирование столов (Flow)

#### Общая логика (единая для всех платформ)
```python
# Псевдокод
async def create_booking(user_id, table_id, date, start_time, end_time, guests):
    # Проверка занятости стола
    if await redis.is_slot_blocked(table_id, date, start_time):
        raise Exception("Стол уже забронирован")
    
    # Блокировка слота в Redis на 10 минут
    await redis.block_slot(table_id, date, start_time, ttl=600)
    
    # Расчёт суммы
    duration = (end_time.hour - start_time.hour) + (end_time.minute - start_time.minute) / 60
    price = await db.get_table_price(table_id) * duration
    
    # Создание брони
    booking = await db.create_booking(user_id, table_id, date, start_time, end_time, guests, price)
    
    return booking
```

#### Шаг 1: Выбор даты
- Инлайн-календарь (aiogram: `aiogram_calendar`, vkbottle: аналог, Max: встроенный календарь)
- Доступные даты: от сегодня + 1 день до + 30 дней
- Блокировка прошедших дат

#### Шаг 2: Выбор времени
- Список доступных слотов: 12:00 — 23:00 с шагом 30 минут
- Проверка занятости через Redis
- Блокировка слота в Redis на 10 минут при выборе

#### Шаг 3: Количество человек
- Валидация: `guests_count <= table.capacity`
- Рекомендация стола при превышении вместимости

#### Шаг 4: Выбор стола
- Список свободных столов на выбранную дату/время
- Опционально: карта столов (картинка с номерами)

#### Шаг 5: Внос депозита
1. Расчёт суммы: `price_per_hour * duration_hours`
2. Генерация счета через ЮKassa API
3. Отправка ссылки пользователю
4. Ожидание Webhook от ЮKassa
5. При успехе: изменение статуса на «Оплачено»

**Примечание:** Логика бронирования полностью идентична для всех платформ. Различия только в UI (inline-кнопки Telegram, клавиатура VK, нативные компоненты Max).

### 3.4. Промокоды и лояльность

#### Общая логика (единая для всех платформ)
```python
# Псевдокод
async def apply_promo(booking_id, code):
    promo = await db.get_promo_by_code(code)
    
    if not promo or not promo.is_active:
        raise Exception("Промокод не найден или неактивен")
    
    if promo.current_uses >= promo.max_uses and promo.max_uses > 0:
        raise Exception("Промокод исчерпан")
    
    # Применение скидки
    booking = await db.get_booking(booking_id)
    discount = calculate_discount(booking.deposit_amount, promo)
    
    await db.apply_promo_to_booking(booking_id, promo.id, discount)
    await db.increment_promo_uses(promo.id)
    
    return discount
```

#### Типы промокодов
- **Процентная скидка:** 10%, 15%, 20%
- **Фиксированная сумма:** 500 ₽, 1000 ₽

#### Жизненный цикл
1. **Создание (админ):**
   ```bash
   /create_promo [имя] [скидка] [тип] [кол-во_использований]
   ```

2. **Рассылка:** Отправка кода пользователям через рассылку

3. **Применение:**
   - При бронировании пользователь вводит код
   - Система проверяет валидность
   - Скидка применяется к депозиту

4. **Автоматическое закрытие:**
   - При достижении `max_uses`
   - По истечении `valid_to`

**Примечание:** Промокоды работают на всех платформах. Поле `platform` в таблице `promocodes` позволяет ограничить использование промокода для конкретной платформы.

```
│   │   ├── __init__.py
│   │   ├── telegram.py           # Адаптер Telegram
│   │   ├── vk.py                 # Адаптер VK
│   │   └── max.py                # Адаптер Max
│   ├── telegram/
│   │   ├── __init__.py
│   │   ├── handlers.py           # Обработчики команд (адаптер)

│   │   ├── handlers.py           # Обработчики команд (адаптер)
│   │   └── states.py             # FSM состояния (адаптер)
│   ├── max/
│   │   ├── __init__.py
│   │   ├── handlers.py           # Обработчики команд (адаптер)
```
